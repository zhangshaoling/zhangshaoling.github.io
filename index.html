背景

我不是程序员，也不懂运营。但我搭了一套系统，让 AI Agent 自己去接单、交付、收钱。

整套系统跑在 Windows 本地，核心引擎是自研的 Hermes Agent 框架。核心思路：把重复劳动交给 AI，人只管决策和审核。

系统架构

┌─────────────────────────────────────────────┐ │ Hermes Agent 核心 │ │ │ │ Cron 定时巡航 ──┐ │ │ SSE 实时通道 ──┼── 任务匹配 + 自动申请 │ │ Hook 事件驱动 ─┘ │ │ │ 内容生成 + 自动交付 │ │ │ │ │ 收款 + 数据统计 │ └─────────────────────────────────────────────┘

三个入口同时工作：

  • Cron 定时巡航：每 5/10/15/30 分钟扫描任务大厅
  • SSE 实时通道：有新任务即时推送，不用轮询
  • Hook 事件驱动：工具调用、会话结束等事件自动触发后续动作

省钱黑科技

1. 多模型路由

不是所有任务都需要最强模型。我搭了一条降级链：

主力 DeepSeek v4-flash
便宜，缓存命中 ¥0.02/M
↓
免费 GitHub Models
gpt-4o-mini 免费额度
↓
零成本 Ollama 本地
qwen2.5:7b
↓
免费 LongCat-Flash-Lite
5000万 token/天

日常 90% 的任务走本地模型或免费额度，主模型只处理需要推理的复杂任务。

2. Token 精确打击

浏览器自动化时，不用 state 全量 dump（30-40KB/次），改用 eval + 精确选择器（几十字节/次）。

// 错误做法：每次调用烧 5k token
state()

// 正确做法：精确取目标数据
eval("document.querySelector('.balance')?.textContent")

8 次调用省了 5k token。

3. 记忆系统

Agent 有自己的记忆：

  • 向量记忆库：696 条长期记忆，语义检索
  • 工作记忆：工具调用日志，供后续任务参考
  • 自动收集器：每 6 小时扫描对话，蒸馏重要信息存入知识库

最意外的发现

搭系统的过程中，我写了一门编程语言。

叫 Ku，核心理念是 thought = code = memory——代码就是数据，数据就是记忆，记忆就是思想。

// 自举的 lexer 和 parser
thought tokenize(input) {
  let tokens = []
  let pos = 0
  // ... 词法分析逻辑
  self.tokens = tokens  // 运行时重写自己的 AST
  return tokens
}

Ku 的 lexer 和 parser 是用 Ku 自己写的（自举），Python 只是 bootstrap 的脚手架。

已经开源了：github.com/zhangshaoling/ku

踩过的坑

  1. 内容审核比你想的严：提到具体平台名会被判"站外引流"
  2. "免费"不免费：数字资产平台标"免费"，实际自动定价 100+ UT
  3. API Key 会过期：批量操作可能触发安全机制，密钥被吊销
  4. 最低悬赏有门槛：任务最低 50 UT，不是想标多少就多少
  5. npm 在 Windows 上经常坏：用 yarn 或 pnpm 替代
